24  Experiment with Turing Machines

% noend hides “end for”; drop it to keep them

In this chapter we collect some resources to experiment with Turing machines at the instruction-by-instruction level, in particular you can find some simulators of variations of Turing machines (1-tape in Section 24.1, k-tapes in Section 24.2, nondeterministic in Section 24.3). As we will see in Chapter 25 they all turn out to be equivalent.

In all cases we use tape(s) infinite to the right only. The leftmost cell always holds the end marker ▶.

Warning

All the simulators are experimental and use Pyodide to run the simulation. They might not run properly on small screens such as smartphones. Please report any bug.

24.1 A 1-tape deterministic Turing machine simulator

Below you have a simple implementation of a simulator of a (deterministic) Turing machine using 1-tape. The input starts right after ▶, in cell 1, where the head begins. Write the transition table below (one rule per line), set the input, and press Run or Step. The diagram under the tape shows the states: the current state and the transition just used are highlighted.

Format: state symbol -> new_state write move, with move in L, R, S (stay). Blank is _. The left end marker ▶ can be typed as > (or pasted as ▶). * matches any symbol (and, as the written symbol, keeps it). # starts a comment. If no rule applies, the machine rejects. The machine also rejects if it tries to move left of ▶, to overwrite ▶, or to write ▶ elsewhere.

24.2 A k-tapes deterministic Turing machine simulator

The machine has k tapes (choose k below). The input word is written on tape 1, starting in cell 1; the other tapes start empty. All the heads start on cell 1, and in every step all heads read, write and move together. Write the transition table (one rule per line), set the input, and press Run or Step. The diagram under the tapes shows the states: the current state and the transition just used are highlighted, and you can drag the states around.

Format: state reads -> new_state writes moves, where reads, writes and moves are strings with exactly one character per tape (tape 1 first) and each move is L, R or S (stay). Example for k = 2: q0 a_ -> q0 aa RR means "in q0, if tape 1 shows a and tape 2 shows a blank, write a on both tapes and move both heads right". Blank is _; the left end marker ▶ can be typed as > (or pasted as ▶). * in reads matches any symbol of that tape, and in writes it keeps the symbol. If several rules match, the one with the fewest * is used; two rules that can match the same symbols without one being more specific are refused, so the machine stays deterministic. # starts a comment. The machine rejects if no rule applies, or if a head would move left of ▶, overwrite ▶, or write ▶ elsewhere.

24.3 A Nondeterministic Turing machine simulator

The machine is nondeterministic (and for simplicity we only use 1-tape): several rules may apply to the same state and symbol, and every choice is explored in parallel. Each card below is one configuration (state, tape and head position) of one computation branch, and a single Step advances all branches at once. The word is accepted as soon as some branch reaches the accept state. The diagram shows the states: the active states and the transitions just used are highlighted, and you can drag the states around.

Format: state symbol -> new_state write move, with move in L, R, S (stay). Several rules may share the same state and symbol: all of them are tried in parallel. Blank is _. The left end marker ▶ can be typed as > (or pasted as ▶). * matches any symbol (and, as the written symbol, keeps it). # starts a comment. A branch dies when it reaches the reject state, when no rule applies, or when it tries to move left of ▶, to overwrite ▶, or to write ▶ elsewhere. A configuration that was already visited is not explored again.
